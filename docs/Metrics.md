# Метрики:
1. Mетрика отслеживает общее количество HTTP-запросов, поступивших в приложение:
```commandline
REQUESTS = Counter('app_requests_total', 'Total HTTP requests', ['method', 'endpoint']).
```
Показывает, какие запросы чаще всего обрабатываются приложением (см. список в README.md), используется для выявления перегруженных эндпоинтов.

2. Метрика измеряет задержку (латентность) обработки HTTP-запросов (эндпоинт `/stress`):
```commandline
REQUEST_LATENCY = Histogram('app_request_latency_seconds', 'Request latency', ['method', 'endpoint'])
```
Показывает время, необходимое для обработки запросов, позволяет выявить потенциальные узкие места в производительности приложения.

3. Mетрика отслеживает общее количество ошибок, возникающих при обработке HTTP-запросов (в эндпоинте `/errors` ошибка создаётся искусственно с помощью `random.choice([True, False])`)
```commandline
ERRORS = Counter('app_errors_total', 'Total errors', ['method', 'endpoint'])
```
Позволяет отслеживать количество ошибок (если кол-во ошибок больше 1, то настроен alert в Telegram), что необходимо для мониторинга стабильности работы приложения.

4. Метрика предоставляет суммарную информацию о времени, затраченном на обработку HTTP-запросов (энпоинт `/stress`).
```commandline
REQUEST_TIME_SUMMARY = Summary('app_request_processing_time_seconds', 'Time spent processing requests', ['method', 'endpoint'])
```
Позволяет получить общее представление о времени обработки запросов, что необходимо для анализа производительности и выявления слишком долгой обработки запросов.
